# Cache warmer — giorgostsamis.gr

Αντικαθιστά τον LiteSpeed Cache Crawler, που δεν τον παρέχει ο hosting.
Επισκέπτεται όλες τις σελίδες του `sitemap_index.xml` ως επισκέπτης (χωρίς cookies),
μία φορά με desktop και μία με mobile User-Agent (γιατί το «Cache Mobile» είναι ενεργό),
ώστε το LiteSpeed να έχει έτοιμο αντίγραφο πριν φτάσει ο πελάτης.

**Δεν αλλάζει τίποτα στο site.** Μόνο διαβάζει σελίδες, όπως ένας επισκέπτης.

## Πώς μοιράζεται η δουλειά
Το site έχει 54 sitemaps προϊόντων (περίπου 10.800 προϊόντα αν είναι πλήρη, ×2 για
desktop/mobile). Αυτά δεν χωράνε σε μία εκτέλεση χωρίς να φορτωθεί ο server, άρα:
- **Σελίδες, κατηγορίες και μάρκες:** γεμίζουν σε **κάθε** εκτέλεση (κάθε 6 ώρες).
- **Προϊόντα:** χωρίζονται σε **12 κομμάτια**. Κάθε εκτέλεση γεμίζει το επόμενο κομμάτι
  (~900 προϊόντα, ~1.800 επισκέψεις, ~2 ώρες την πρώτη φορά, πολύ λιγότερο μετά).
- **Πλήρης κύκλος σε 3 ημέρες**, ενώ η cache του LiteSpeed κρατάει 7 ημέρες. Άρα κάθε
  προϊόν ξαναγεμίζει πριν λήξει.
- Μετά από «Purge All», οι κατηγορίες ξαναγεμίζουν σε 6 ώρες και όλα τα προϊόντα σε 3 ημέρες.
  Για γρηγορότερο γέμισμα: Run workflow χειροκίνητα, ή `--chunk N` για συγκεκριμένο κομμάτι.

## Προστασίες για τον server
- 1 αίτημα τη φορά, 1,5 s παύση ανάμεσα.
- Αν μια σελίδα αργήσει πάνω από 8 s ή ο server δώσει 5xx/429, περιμένει 30 s.
- Σταματά μόνο του μετά από 20 σφάλματα ή 150 λεπτά.
- Παραλείπει καλάθι, checkout, λογαριασμό, wishlist, αναζήτηση και tags.
- Σειρά: πρώτα σελίδες και κατηγορίες, μετά μάρκες, τελευταία τα προϊόντα.
- Τα αιτήματα έχουν `WebionCacheWarmer/1.0` στο User-Agent, ώστε να ξεχωρίζουν
  στα logs και να εξαιρεθούν από analytics αν χρειαστεί (δεν τρέχουν JS, άρα δεν
  στέλνουν GA4/Ads/Meta events).

## Επιλογή Α: GitHub Actions (προτείνεται)
1. Νέο private repo, π.χ. `webion/tsamis-cache-warmer`.
2. Ανέβασε `warm_cache.py`, `README.md` και `.github/workflows/warm-cache.yml`.
3. Actions → «Warm LiteSpeed cache» → **Run workflow** με `limit = 20` για δοκιμή.
4. Δες στο log ότι οι σελίδες δίνουν `miss` την πρώτη φορά και `hit` τη δεύτερη.
5. Από εκεί και πέρα τρέχει μόνο του κάθε 6 ώρες.

## Επιλογή Β: cron σε NAS ή server
Χρειάζεται μόνο Python 3.8+.
Το cron πρέπει να τρέχει σε UTC ή να ταιριάζει με τα 6ωρα διαστήματα (00, 06, 12, 18 UTC),
ώστε κάθε εκτέλεση να παίρνει νέο κομμάτι.
```
17 */6 * * * /usr/bin/python3 /path/to/warm_cache.py --rotate 12 --interval-hours 6 >> /path/to/warm.log 2>&1
```

## Χειροκίνητα, μετά από purge
```
python3 warm_cache.py --rotate 12              # σελίδες/κατηγορίες + το τρέχον κομμάτι προϊόντων
python3 warm_cache.py --rotate 12 --chunk 0    # σελίδες/κατηγορίες + το 1ο κομμάτι
python3 warm_cache.py --limit 50               # μόνο τα πρώτα 50 URL (δοκιμή)
python3 warm_cache.py --only mobile            # μόνο mobile
```

## Τι δείχνει το αποτέλεσμα
Στο τέλος τυπώνει πόσα ήταν ήδη `hit`, πόσα ήταν `miss` (και τώρα μπήκαν στην cache),
και τις 10 πιο αργές σελίδες χωρίς cache — αυτές είναι οι υποψήφιες για βελτίωση κώδικα.
